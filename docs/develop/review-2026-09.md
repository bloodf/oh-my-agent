# Review 2026-09: extension, console, website, demo

Reviewed on 2026-09-14 against `main` at `27ac17e` (version 1.5.1). The goal was to prove every surface works before the next round of feature work, and to turn anything broken into a short, ordered fix list.

This is a findings report. Nothing in it has been fixed yet. Each finding has a proposed disposition that needs sign-off before a fix PR opens.

## Resolution

Fixed on 2026-09-15 in five groups, recorded as T-1801 to T-1805 under EP-18 in the delivery tree. The three decisions below were taken as recommended: `web-next` is removed (ADR-018), remote operators without full control may edit only an agent's name, description, model, thinking level, and rooms, and a parity test guards the demo mock.

Every P0 and P1 finding is fixed, and each fix has a test that fails without it. All P2 and P3 findings are fixed except these:

| Id | State | Reason |
|---|---|---|
| D-10 | Partial | Boot unwind, invalid console port, shutdown during spawn, and wired web routes are tested through `bootDaemon`. The inference gateway lifecycle, stop mid-boot, usage single-flight, and the attachment cleanup timer need a real OMP session or long timers. |
| C-24 | Partial | The React sign-in validates the ticket. The inline copy in `web/index.html` stays, because the token-entry page loads without `app.js`. |
| W-04 | Partial | The website declares the console dependencies it compiles, and Vercel installs with frozen lockfiles. A website-only install still fails, because Tailwind resolves `web/src/index.css` imports from `web/`. |
| C-19, C-28 | Fixed, untested in a browser | The Open review popup timing and the partial definition save message are verified by reading. |

## Verdict

The build is healthy and the test suite is stable. The product has a handful of real defects that the suite cannot see, because the browser suite bypasses the daemon's static-file auth and nothing gates the website or the demo mock.

Fix the P0 and P1 items below before starting features. Most P2 and P3 items can land alongside feature work.

| Surface | Verdict |
|---|---|
| Extension, daemon, CLI | Solid. One remote-mode gate hole needs an owner decision. |
| Web console (`web/`, `src/console/`) | Broken on a real daemon in three documented flows: reload, Mermaid, and rooms past 500 messages. One data-loss bug in Plans. |
| `web-next/` | Unauthenticated token proxy on all interfaces. Recommend deleting it. |
| Demo (`website/console`) | Works. Mock drifted from the daemon in several places and nothing catches drift. |
| Website | Builds and renders cleanly. Three false product claims and broken social-card URLs. Not in CI. |

## Decisions needed

1. **`web-next`: recommend delete.** It duplicates the console with hand-mirrored types. It lacks threads, chats, Changes, definition editing, and remote auth. It costs a CI install, a typecheck, and a 180-second test. It carries C-01, C-07, and a copy of C-02. It is not in the npm package.
2. **D-01: what may a remote operator without full control change?** Either gate `sandbox`, `tools`, `mcps`, and `body` like `workspace`, or document that remote operators can relax an agent's sandbox. The review recommends gating them.
3. **Mock parity guard.** Recommend one test that compares the mock's route table with the daemon's, plus a smoke that fails on unknown routes and asserts frame types. No new framework.
